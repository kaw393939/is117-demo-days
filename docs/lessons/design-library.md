# Build a design library you’ll actually use

**Why it matters:** Good design references give you choices. The useful part isn’t collecting screenshots. It’s noticing a choice and deciding whether it would work for your audience.

## Try it

Take one example from each category: **brand character**, **persuasion**, and **visual composition**. Give each example a short source note:

- **What I saw:** “The product page puts the size guide next to the size selector.”
- **Why it might help:** “A first-time shopper doesn’t have to leave the page to check fit.”
- **What I’ll try:** “Put real measurements by the size options. Ask a shopper where they’d check whether it fits.”

Compare a layout with a strong reading order to one that uses contrast or an unexpected arrangement. Don’t copy either. Borrow one principle and test what it does for the same offer.

## Share the library

If your team works from forks, the leader’s repository is the shared copy. Use a branch and a pull request to propose your page. Once the team merges it, sync your fork from the shared repository, then check that your fork shows the merged work. Don’t overwrite your unmerged changes just to make the fork match.

## Check your work

Can you point to evidence for each observation? Does the persuasion choice actually help the shopper decide? Don’t imply fake scarcity or treat a brand’s own claim as independent proof.
