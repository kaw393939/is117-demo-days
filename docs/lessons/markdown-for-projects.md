# Markdown: make your project easy to follow

**Why it matters:** The person reviewing your work shouldn't have to search six pages to find what you built. A clear README gives them a useful starting point.

## Try it

Create a short README for a site you know. Use headings for **What it does**, **How to try it**, and **What I checked**. Link to the demo and one relevant GitHub issue. If there’s a setup command, put it in a code block and say where to run it.

A useful check is more specific than “tested the site.” Try “On my phone, I chose size M, added two shirts, and saw the expected total.” Use your actual result. If the browser preview doesn't use the same database as the local app, say so.

## Check your work

Preview the Markdown on GitHub. Can a classmate find the demo and one useful check without your help? Try every link. Add a plain description to any image that communicates an important result.
