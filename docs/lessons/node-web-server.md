# Node.js: serve one page and see a request

**Why it matters:** A page on your screen and a server response aren't the same thing. Seeing a request and its status makes it easier to diagnose later projects.

## Try it

In a copy of the class starter, run the start command in its README. Open the local address it prints, then change a visible line of text and load the page again. Restart the process if your server doesn't reload changes automatically.

Before opening each path, predict what the server will send. Start with `/`; use `/about` once your starter defines it. Both should return 200. Then open `/missing-page`. Compare the page that works and the missing path in the browser’s Network tab. The working page should have a successful response, and the missing path should report that it wasn't found. If both appear successful, check how the starter handles paths it doesn't recognize.

## Check your work

Explain the two paths, their status codes, and the part of the code that chose each response. Write the start command so a classmate can try it. A browser-only preview can show the interface, but it doesn't prove that a Node server or SQLite is running.
