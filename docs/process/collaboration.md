# Collaboration and equal contribution

Plan equal workloads and make responsibilities visible. Each partner contributes to **design, development, and quality assurance**; all members share responsibility for integration and the final result.

## Example allocation for two people

| Work | Partner A | Partner B | Review / verification |
| --- | --- | --- | --- |
| Discovery and specification | Customer journey and acceptance criteria, 2 points | Data flow and scope decisions, 2 points | Agree together |
| Design | Public service/product flow, 2 points | Staff review flow, 2 points | Exchange design feedback |
| Development | Intake and validation, 5 points | Storage and staff review, 5 points | Integrate and explain interfaces |
| QA | Test B's staff flow, 2 points | Test A's intake flow, 2 points | Record/retest bugs |
| Handoff and demo | Own contribution notes and demo, 1 point | Own contribution notes and demo, 1 point | Joint rehearsal |
| **Planned total** | **12 points** | **12 points** | Rebalance if scope changes |

Points estimate relative effort, not grades. A trio can divide three comparable vertical slices, each with design, implementation, and cross-review. A member who owns an unfamiliar or difficult part may need a smaller feature count for equal effort.

## Practical Git workflow

Create small task issues that reference the spec. Use a branch for a bounded change, commit meaningful work, and have your partner review it before integration when practical. Explain how to run the change and what was checked. Merge early enough to find integration problems.

Review evidence can be a pull request, issue discussion, recorded peer test, or design feedback with the resulting change. Keep a brief contribution log; do not reconstruct a fictional process at the end.

## When the plan changes

Compare actual effort with the allocation at each review. Record a revised owner/scope/estimate and rebalance remaining work. If someone is absent or a partnership is not functioning, contact the instructor privately through Canvas rather than posting personal circumstances in public issues.

Use the [collaboration template](/templates/collaboration) and include individual contributions in the portfolio and Demo Day explanation.
