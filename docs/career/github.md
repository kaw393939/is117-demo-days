# Build a professional GitHub portfolio

Your portfolio website tells the story. GitHub supplies evidence: source code, documentation, specifications, issues, reviews, and a record of how the work developed. Help someone unfamiliar with the course understand what you built and what you contributed.

## Set up a clear profile

Use a recognizable display name, a short bio, and a link to your portfolio. A useful bio describes your present stage and interests: “NJIT student building web projects with JavaScript, Git, and AI-assisted development.” Adjust the technologies to match your actual work.

Consider adding a **profile README**. For a standard personal account, GitHub displays it from a public repository whose name matches your username, with a nonempty `README.md` in the root. This special profile repository is separate from the repository hosting your portfolio website. [GitHub profile README instructions](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme).

A simple starting point:

```md
# Hi, I'm [Name]

I'm a [major] student at NJIT interested in [career direction].
I'm developing my skills in [technologies I can explain and use].

## Selected work
- Portfolio: [live site URL]
- Plain White T-Shirt company: [repository and live site URLs]
- Group business project: [repository and live site URLs]
  My contribution: [specific design, development, and QA work]

## Connect
- LinkedIn: [profile URL]
- Professional contact: [appropriate contact route]
```

Replace the placeholders before publishing. Use public-facing contact information you are comfortable sharing.

## Pin the work you want someone to inspect

Pin your portfolio, individual T-shirt repository, and shared business repository where available. GitHub supports pinning repositories and gists through **Customize your pins** on your profile. A shared repository can be highlighted without creating a duplicate copy that obscures your team's history. [GitHub pinning instructions](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile).

Give repositories meaningful names and short descriptions. Add the live site to the repository's About/website information when appropriate. Someone should be able to find a working demonstration from the repository and the code from the live site.

## Make each project understandable

A useful project README includes:

| Section | What the reader should learn |
| --- | --- |
| Purpose | Business problem, audience, and main workflow |
| Demo | Live link, labeled screenshots, and how to try it |
| Features and status | What works, what is simulated, and what is unfinished |
| Technology | Tools used and a brief explanation of the data flow |
| Setup | Prerequisites, install/run commands, database setup if needed |
| Process | Links to competitive research, feature priorities, and specification |
| Verification | QA results, relevant tests, fixes, and known limits |
| Contributions | Each member's specific work, linked to issues/reviews when useful |
| Attribution | Sources for reused code, content, fonts, and imagery |

Keep real credentials and private data out of the repository. If configuration is required, document variable names using an example file with placeholders. Test the setup instructions from a clean checkout when practical.

## Show collaboration honestly

Use descriptive commits such as “Validate service request inputs” or “Add size-guide keyboard navigation.” Keep issues and reviews connected to actual decisions and changes. A useful review explains what was checked, identifies a problem, or confirms an acceptance criterion.

AI assistance is compatible with a professional repository when you understand the result, acknowledge relevant assistance, and verify the work. Do not manufacture commits, contributions, customer usage, or test results to make the project appear more substantial. Activity counts alone do not show quality.

## Before Demo Day

- The profile links to your portfolio and presents your current interests accurately.
- The portfolio, T-shirt, and group repositories are easy to find.
- Every featured repository explains its purpose and has working links.
- Your individual group contribution is identifiable.
- Setup, specifications, and QA evidence are understandable to another student.
- No placeholder claims or broken image links remain in the published README.

Bring the repository into your demo when it helps substantiate a decision or contribution. Pair this with your [LinkedIn profile](/career/linkedin) and [course-based résumé](/examples/student-resume).
